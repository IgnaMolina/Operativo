1. Let´s start whit the basics:
	-  A running program does a very simple thing: It execute instructions, the processor **fetches** an instruction from memory, **decodes** and **executes** it. After it is done with this instruction, the processor moves on to the next instructor. We have just described the basics of the Von Neumann model of computing.
	- In fact, there is a body of software that is responsible for making it easy to run programs, we call this the **Operating System**, or the **OS** as we will call it from now on, in charge of making sure the system operates correctly anda efficiently in easy-to-use manner.  The primary way the OS does this is through a general technique that we call **virtualization**.

2. How the OS manage the resources of the computer. 
	- The OS takes a physical resource, such as the memory, the processor, or a disk; and transforms it into a mor general, powerful, and easy-to-use **virtual** form of itself. Sometimes we can refer to the OS as a **virtual machine**.
	- The OS also provides some interfaces (**APIs**), it´s exports a few hundred **system calls** that are available to applications, programs use it to access memory and devices, and other related actions, we also sometimes say that the OS provides a **standard library** to applications. 
	- The virtualizations allows many programs to run at the same time, the OS is sometimes known as a **resource manager**.  The CPU, memory, and disk is a resource of the system that the operating system´s role to manage those resource the most efficiently and fairly way.

- Persistence:
	- The third major theme of the course is **persistence**. In system memory data can be easily lost; when power goes away or the system crashes, any data in memory is lost. We need hardware and software to be able to store data persistently. Unlike the abstractions provide by the OS for the CPU and memory, the OS does not create a private, virtualized disk for each application. Users will want to share information that is in files. 	- For performance reasons, most file systems first delay such writes for a while, hoping to batch them into a larger groups. Most file systems incorporate some kind of intricate write protocols, such as journaling or copy-om-write, this in order to ensure that if a failure occurs during the write sequence, te system can recover to reasonable state afterwards.
 - Design Goals:
	 - An OS actually take physical resources, such as we already mentioned CPU, memory, or disk, and virtualizes them to use it later. Such massive system have some **design goals** such as:
		 - Build up some **abstraction** in order to make the system convenient and easy to use. They make possible to write a large program by dividing it into small and understandable pieces. Like writing in C whiteout thinking in assembly.
		 - Another goal is to provide high **performance**, another way to say this is our goal is to **minimize the overheads** of the OS. Virtualization and making the system easy to use are well worth it, but not at any cost. We must strive to provide virtualization and other OS features without excessive overheads.
		 - another goal will be to provide **protection** between applications, as well as between te OS and applications, we want to make sure that the malicious or accidental bad behavior of one does not harm other or the OS itself.
		 - Lastly we want to give **reliability**, which is making sure that when it fails, all applications running on the system fail as well.
